# 学习计划：Loop Engineering（Agent 循环工程）

> 用户场景：面试 / 会议前补课——目标是**对答如流**，不是独立实现。阶梯的里程碑和自测题据此设计：第 3-4 级不考"能不能写代码"，考"能不能在对话里把框架用在新场景上、扛住追问"。

## 第 6 步 · 学习阶梯

### Lv.1 完全初学者

1. **应理解**：agentic loop 是什么；tool_use → 执行 → tool_result 的三段式；四层演进阶梯（prompt→context→harness→loop）；五个必备部件
2. **"掌握"的样子**：能不看笔记复述一句话定义和四层阶梯
3. **重点关注**：循环 vs 自动化的分水岭——**目标验证步**；模型自己不执行任何东西，只请求
4. **进阶里程碑**：能用 2 分钟给一个外行讲清楚"agent loop 和只调一次 API 有什么不同"，不卡壳
5. **动手练习**：挑一个具体例子（比如"agent 修一个代码 bug"），把五个部件（trigger/goal/tools/verification/stopping rule）逐个对应说出来——不用写代码，说出来就行
6. **常见错误**：把"agent"和"聊天机器人"混为一谈；以为循环需要好几个不同模型协作；忘记模型不能自己执行工具
7. **自测题**：为什么模型自己不执行任何东西？谁来执行？

### Lv.2 基本理解

1. **应理解**：`stop_reason` 的几种状态；compaction（压缩）vs context editing（编辑）的区别；prompt caching 的前缀敏感性；护栏的具体类型（迭代上限/成本预算/无进展检测/熔断/人工介入点）
2. **"掌握"的样子**：能不混淆地讲清楚"上下文快满了会发生什么、有哪几种应对手段"
3. **重点关注**：**compaction 和 context editing 是两件不同的事**——一个是总结，一个是剪枝，这是最容易被混着讲错的一对概念
4. **进阶里程碑**：给定一个失败场景描述，能指出"哪种护栏本可以防住它"
5. **动手练习**：拿资源 4（Cyera 报告）里 PocketOS 和 Replit 两个案例，分别说出"如果加了哪种护栏，这次事故本可以避免"
6. **常见错误**：把 compaction 和 context editing 当成同一件事；以为"扩大上下文窗口"就能解决 context rot
7. **自测题**：compaction 和 context editing 有什么区别？

### Lv.3 实际使用者（对你：能把框架套用到新场景，不是能写代码）

1. **应理解**：五视角各自的立场和证据；目前领域最大的悬而未决问题（护栏是否真提升成功率）
2. **"掌握"的样子**：拿到一个没见过的场景（比如"公司想用 agent 自动分诊客服工单"），能当场口头拆出 trigger/goal/verification/stopping rule
3. **重点关注**：**可验证目标设计**——这是整个领域的成败关键，也是面试里最容易被深挖的点
4. **进阶里程碑**：任何一个模糊的任务描述，都能不看提示改写成"触发器+可验证目标"的一句话
5. **动手练习**：挑 3 个假设场景（工单分诊 / PR 审阅机器人 / 报销单审核），每个场景在 60 秒内口头说出它的 trigger/goal/stopping rule
6. **常见错误**：写出机器不可判定的目标（"让它更好"）；忘了设停止规则；把"agent 能做 X"和"agent 该无人值守地做 X"混为一谈
7. **自测题**：给一个模糊需求"帮我把收件箱清干净"，你会怎么把它改写成一个可验证目标？

### Lv.4 问题解决者（扛住追问）

1. **应理解**：矛盾图谱里的核心分歧（护栏是解法还是止损）；Rice 定理/Goodhart 那条结论的正确措辞（是"尚待核实的强断言"，不是"已证明"）；具体事故案例；经济激励批判
2. **"掌握"的样子**：被问"这是不是纯炒作"时，能给出结构化、不慌乱的回答
3. **重点关注**：**区分"loop engineering 这个词"（炒作、短命）和"它指向的真实问题"（持续存在）**——这是应对刁钻追问的最高杠杆点
4. **进阶里程碑**：面对"所以这就是纯炒作吧"这句话，能用"这个词才一个多月大、但有 2001 年 MAPE-K 先例、有真实生产事故、但也有厂商按 token 计费的利益驱动"这个结构回答，不卡壳
5. **动手练习**：模拟问答——把这三个刁钻问题的回答写下来或说出来：「这不就是加了个 while 循环加重试吗？」「我凭什么信厂商博客说的这些最佳实践？」「这里真正没解决的问题到底是什么？」
6. **常见错误**：把"加护栏能解决循环问题"说成行业共识（这是有争议的，不是共识）；把 Rice 定理那条结论讲成"已证明"而不是"尚待核实"
7. **自测题**：如果面试官说"这不就是加了个 while 循环加重试吗，有什么好谈的"，你怎么接？

### Lv.5 自信的实践者

1. **应理解**：以上全部，整合成一个连贯的叙事；能主动带出前沿问题和治理盲区，展示超出被问范围的深度
2. **"掌握"的样子**：能主导 5-10 分钟的相关对话，不需要对方一直提问带节奏
3. **重点关注**：**知道什么时候该收着说**——深度是通过恰当的保留表现出来的（比如不过度断言 Rice 定理），不是靠堆更多事实
4. **进阶里程碑**：能不看速查表、用自然对话的语气（不是背列表）把速查表内容讲一遍
5. **动手练习**：掐表做一次 5 分钟的模拟独白——"跟我讲讲你对 loop engineering 的了解"，不看笔记，录下来或说给自己听
6. **常见错误**：把对话变成信息倾倒，而不是交流；忘了先问对方"你更想听哪个角度"再展开，而是自顾自讲完全部
7. **自测题**：做完第 6 项的独白练习后自我复盘——有没有举一个真实案例？有没有对不确定的结论做适当保留？有没有主动带出前沿问题？

# 第 7 步 · 2 小时啃下核心 20%

## 那 20% 是什么

| 概念 / 技能 | 为什么它是核心 |
|---|---|
| 循环机制 + 四层演进阶梯 | 几乎必问的框架题,答不出等于没入门 |
| 五部件（尤其可验证目标） | 能把抽象框架套到任何新场景的唯一钥匙,是全领域的第一原理 |
| 一个真实事故案例 | 把"知道概念"和"能对答如流"分开的东西——面试官记不住定义,记得住故事 |
| "护栏是解法还是止损"这个争议 | 展示批判性思考的最高杠杆点,单纯背定义的人答不出这个 |
| "词会过时,问题不会"的框架 | 应对"这是不是纯炒作"这类追问的通用武器 |

## 10 次课

### 第 1 课：循环的骨架——机制与四层阶梯

- **学习目标**：不看资料复述 tool_use→执行→tool_result 三段式,以及 prompt→context→harness→loop 四层演进
- **关键概念**：agentic loop、ReAct、循环 vs 自动化（目标验证步）
- **动手练习**：60 秒内讲清楚"agent loop 和只调一次 API 的区别"
- **推荐资源**：LangChain《The Art of Loop Engineering》
- **完成后的预期结果**：能流畅复述,不卡壳

**5 个复习题**
1. agentic loop 最精炼的一句话定义是什么？
2. 四层演进阶梯从左到右依次是什么？每一层"自动化掉"了什么？
3. 模型自己执行工具吗？如果不是,谁执行？
4. 循环和自动化的分水岭是哪一步？
5. ReAct 和 agentic loop 是什么关系？

### 第 2 课：五个部件——把框架套到具体场景

- **学习目标**：能把 trigger/goal/tools/verification/stopping rule 套用到一个没见过的场景
- **关键概念**：可验证目标、五部件、state/memory
- **动手练习**：挑一个场景（如"agent 自动清理收件箱"）,60 秒内口头拆出五部件
- **推荐资源**：Anthropic《Building Effective Agents》
- **完成后的预期结果**：拿到任何新场景,都能不假思索地拆出五部件

**5 个复习题**
1. 五个部件分别是什么？
2. 为什么"让 app 变好"是个糟糕的目标？
3. "可验证目标"最理想的形态是什么样的？
4. state/memory 为什么建议存在磁盘上而不是对话里？
5. 给"帮我把收件箱清干净"这个模糊需求,你会怎么改写？

### 第 3 课：上下文管理——为什么循环跑久了会变差

- **学习目标**：讲清楚 context window / compaction / context editing / prompt caching 的区别
- **关键概念**：context rot、compaction vs context editing、前缀缓存敏感性
- **动手练习**：解释"如果你的循环跑了 100 轮,会发生什么,你会怎么应对"
- **推荐资源**：本次调研第 0 步扫盲内容（已在对话记录里）
- **完成后的预期结果**：不混淆 compaction 和 context editing

**5 个复习题**
1. compaction 和 context editing 分别是什么？
2. 为什么每一轮都要重发完整历史？
3. context rot 是什么现象？
4. prompt caching 为什么对"前缀"特别敏感？
5. "扩大上下文窗口"能解决 context rot 吗？为什么？

### 第 4 课：护栏与失败模式

- **学习目标**：列出护栏类型,讲清 loopmaxxing 和 IAL
- **关键概念**：max_iterations、no-progress detection（loop fingerprint）、circuit breaker、loopmaxxing、IAL
- **动手练习**：拿一个失败场景,指出该加哪种护栏能防住它
- **推荐资源**：GitHub cobusgreyling/loop-engineering 的 `failure-modes.md`
- **完成后的预期结果**：能举出 3 种具体护栏,各配一个例子

**5 个复习题**
1. loopmaxxing 是什么？为什么它对主观目标必然失败？
2. IAL 是什么的缩写？根因是什么？
3. loop fingerprint 是怎么检测"卡住了"的？
4. 护栏一共有哪几类？
5. 一个没有 max_iterations 的循环,一小时最多能烧多少钱？（记住这个数量级即可）

### 第 5 课：一个真实案例——把抽象讲成故事

- **学习目标**：能完整讲出 PocketOS 或 Replit 案例（谁/触发原因/后果）
- **关键概念**：enforced state vs 自然语言指令
- **动手练习**：像讲故事一样,30-60 秒完整讲一遍案例
- **推荐资源**：Cyera《Agent-Inflicted Damage》
- **完成后的预期结果**：案例讲述流畅,包含"谁/触发什么/后果多严重"三要素

**5 个复习题**
1. PocketOS 事故的三要素分别是什么？
2. Replit 事故里,"不要继续"为什么没起作用？
3. 事故报告里正确的数字链条是什么（7,246 → 344 → 188）？
4. 这类事故的共同教训是什么？
5. 为什么"约束必须下沉到 harness 执行层"这句话成立？

### 第 6 课：五视角速览——展示多角度思维

- **学习目标**：能一句话概括五个视角各自的核心立场
- **关键概念**：实践者/学者/怀疑者/经济学家/历史学家
- **动手练习**：五个视角各用一句话说出立场,连起来讲一遍
- **推荐资源**：`research-brief.md` 第 1 步
- **完成后的预期结果**：不看提示,五句话都能说出来

**5 个复习题**
1. 实践者的核心立场是什么？
2. 学者独家提出的理论限制是什么？
3. 怀疑者认为大家在优化什么错误的变量？
4. 经济学家关注的核心矛盾是什么？
5. 历史学家给出的历史先例是什么？

### 第 7 课：核心矛盾——护栏是解法还是止损

- **学习目标**：讲清楚冲突 A,以及为什么这个问题目前没有答案
- **关键概念**：冲突 A、化解矛盾的关键问题
- **动手练习**：模拟被问"护栏真的有用吗",给出结构化回答
- **推荐资源**：`research-brief.md` 第 2 步
- **完成后的预期结果**：回答里体现"这是有争议的,不是共识"

**5 个复习题**
1. 冲突 A 的两方分别是谁,各自主张什么？
2. 化解冲突 A 的那个关键问题怎么问？
3. 目前有没有直接证据回答这个关键问题？
4. LOCA-bench 的结论跟这个冲突有什么关系？
5. 为什么说双方都拿不出"成功率对比"的直接数据？

### 第 8 课：理论天花板与该有的保留

- **学习目标**：讲清楚 Goodhart/Rice 定理那条结论,并用恰当保留的措辞复述
- **关键概念**：Goodhart's law、验证器局限、第 4 步的核实经验
- **动手练习**：用"核实过的谨慎措辞"复述这条结论
- **推荐资源**：`research-brief.md` 第 4 步
- **完成后的预期结果**：不说"已证明",说"有理论工作指出"

**5 个复习题**
1. 第 4 步同行评审发现了这条结论的什么问题？
2. Goodhart's law 在 AI 领域的应用能追溯到多早？
3. 为什么这条结论不该被讲成"已证明"？
4. 正确的、留有余地的措辞应该怎么说？
5. 这次核实还顺带发现了另一个什么数字错误？

### 第 9 课：应对"这是不是纯炒作"

- **学习目标**：能用历史学家+经济学家组合回答挑战性问题
- **关键概念**：词的寿命 vs 问题的持续性、MAPE-K 先例、token 计费激励
- **动手练习**：模拟回答"这不就是加个 while 循环加重试吗"和"这是不是纯炒作"
- **推荐资源**：`research-brief.md` 第 1 步历史学家/经济学家部分
- **完成后的预期结果**：回答有结构,不慌乱

**5 个复习题**
1. "loop engineering"这个词是什么时候出现的？
2. MAPE-K 是什么,和今天的 agent loop 有什么对应关系？
3. 历史学家对这个词的命运做了什么预测？
