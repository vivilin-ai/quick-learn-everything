## Loop Engineering

> 设计一套系统去驱动 AI agent 自主运行——定义可验证的目标、选择触发方式、选择循环架构、并加上防止成本失控和死循环的护栏——而不是人一句一句手动提示它。`[检索: explainx.ai / datasciencedojo 2026]`

- 术语在 **2026 年 6 月**被命名并流行 `[检索: explainx.ai]`
- 一句话版本：**agentic loop = 一个触发器 + 一个可验证的目标**，agent 一直跑到目标达成 `[检索: datasciencedojo]`

### 演进阶梯（面试最常考的一张图）

> Prompt → Context → Harness → Loop。**每一层都自动化掉了开发者原来手动做的一件事。** `[检索: explainx.ai]`

- **Prompt engineering** —— 优化单次提问的措辞 `[未验证: 通识]`
- **Context engineering** —— 优化喂进上下文窗口的信息（检索什么、压缩什么、丢什么）`[未验证: 通识]`
- **Harness engineering** —— 把 agent 周边的整个系统（工具、沙箱、权限、脚手架）当成一个统一的优化对象 `[检索: explainx.ai]`
- **Loop engineering** —— 闭合反馈回路：系统观察自己的行为、识别失败、无需人介入即可调整 `[检索: explainx.ai]`

### 底层循环本体

> 核心算法极简：**给模型上下文，让它循环调用工具，直到完成。** 真正的工程量全在这句话之外。`[检索: LangChain, The Art of Loop Engineering]`

#### ReAct 范式
- Reason（推理）→ Act（调用工具）→ Observe（读结果）→ 再推理，如此往复 `[未验证: 通识]`
- 是当代 agentic loop 的直接前身，loop engineering 被描述为「从 ReAct 演进而来」`[检索: datasciencedojo]`

#### 一轮迭代（turn / iteration）
- 模型返回**工具调用请求**（tool_use）→ 宿主执行 → 把结果（tool_result）塞回对话 → 再次调模型 `[检索: Anthropic Claude API docs]`
- 循环的退出信号是模型返回的 **stop_reason**：`end_turn`（自然结束）/ `tool_use`（还要调工具）/ `max_tokens`（撞输出上限）/ `pause_turn`（服务端工具暂停，可续跑）/ `refusal`（安全拒绝）`[检索: Anthropic Claude API docs]`

#### 循环 ≠ 自动化
- 自动化是固定步骤照着跑；**循环里有决策**——agent 主动评估「目标达成了吗」并据此决定继续还是停 `[检索: datasciencedojo]`
- **目标验证步（goal-verification step）是二者的分水岭** `[检索: datasciencedojo]`

### 五个必备部件

> 几乎每个 agentic loop 都由这五块组成。`[检索: 多来源综述 2026]`

- **Trigger（触发器）** —— 什么启动它：人说「go」、定时任务、新工单、PR 被打开 `[检索]`
- **Goal（目标）** —— 「完成」长什么样，**最好机器可判定**。「让 app 变好」是死循环配方；「让所有测试通过」「每条论断都有引用来源」才是真终点线 `[检索]`
- **Tools / Execution（执行）** —— agent 得真能做事并看到结果：跑代码并读报错、搜网页并读回来的内容。理想情况下调用的是**已验证的、有名字的 skill** `[检索]`
- **Verification（验证）** —— 真去检查结果，而不是让 agent 自己宣称做完了 `[检索]`
- **Stopping rule（停止规则）** —— 把循环驱动到一个**有名字的终态** `[检索]`
- **实战案例（第 7B 第 2 课，用户自己拆解）**：「清理收件箱」的目标若写成"没有未读邮件"，会被"全标已读"钻空子——是 Goodhart 陷阱的具体样本；改写为"需回复邮件都已回复+按发件人归档"后堵住了漏洞，但又暴露新坑：**目标不该系在 agent 控制不了的人类动作上**（"用户已回复"应改为 agent 止步于"生成建议+escalate"）`[用户]`
- **State / Memory（状态）** —— 进度与决策跨轮持久化，**写在磁盘上而不是留在对话里** `[检索]`

### 上下文管理

> 循环跑得越久，上下文越胀。这是 loop engineering 与单次调用最本质的差别之一。

- **Context window（上下文窗口）** —— 每次请求能塞进去的 token 上限；对话是**无状态**的，每轮要重发全部历史 `[检索: Anthropic docs]`
- **Compaction（压缩）** —— 接近窗口上限时把早期历史**总结**成摘要块 `[检索: Anthropic docs]`
- **Context editing（上下文编辑）** —— 把陈旧的工具结果 / thinking 块**直接清除**（是剪枝，不是总结）`[检索: Anthropic docs]`
- **Prompt caching（提示缓存）** —— 前缀匹配复用；**前缀里任何一个字节变了，后面全部失效**。稳定内容在前、易变内容在后 `[检索: Anthropic docs]`
- 上下文填满会**静默劣化输出质量**，是循环失败模式之一 `[检索]`

### 护栏（Guardrails）

> 防止成本失控和无限循环。这是「能 demo」和「能上生产」的分界。

- **硬迭代上限**（max_iterations）`[检索]`
- **Token / 成本预算**、**墙钟超时** `[检索]`
- **No-progress detection / loop fingerprint** —— 对每步的工具调用+结果做哈希，**连续三次指纹相同 = 卡住了** `[检索]`
- **Circuit breaker（熔断）** `[检索]`
- **Human-in-the-loop checkpoint** —— 不可逆操作前卡人工确认 `[检索]`
- 反例：目标循环没有 max_iterations，**一小时能烧掉 $500** `[检索]`

### ⚠️ 失败模式

- **Loopmaxxing** —— 假设「无限跑下去总会跑对」。对主观 / 不可量化的目标必然失败；与更早的 "tokenmaxxing"（以为加大推理预算就能解决逻辑错误）是同一种迷信 `[检索: bdtechtalks 2026-06-22]`
- **无限反思循环** —— 烧 token 但零进展 `[检索]`
- **幻觉工具调用** —— 触发真实世界的后果 `[检索]`
- **上下文填满 → 输出静默劣化** `[检索]`
- **无停止条件 → token 花费失控** `[检索]`

## 生产事故与失败案例 `[检索: Cyera Research, "Agent-Inflicted Damage" 2026]`

- Cyera Research 分析了 2023-09 至 2026-05 期间 **7,246 条公开事故记录**（来源含 AI Incident Database、OECD 追踪器），筛出 **344 起**与企业相关的已验证事故；其中 **188 起**是「无攻击者参与、自主 agent 直接在生产系统造成损害」的确认案例 `[检索, 第 4 步同行评审修正：原引用误将 344 当作"无攻击者直接致损"数字，正确数字是 188]`
- **PocketOS**：Cursor agent 因凭据不匹配（本应上报）九秒内清空生产数据库及备份 `[检索]`
- **Replit**：agent 在代码冻结期删掉 1,206 条高管记录——「不要继续」是指令而非被强制执行的状态 `[检索]`
- **Uber**：四个月烧完全年 AI 预算，随后设每人每工具每月 $1,500 上限（2026-06 报道）`[检索]`
- **核心教训**：自然语言指令对模型是建议，不是可强制约束；约束必须下沉到 harness 执行层 `[检索: 实践者视角]`

## 理论天花板 `[检索: 学者视角]`

- **Rice 定理 + Goodhart 定律** 共同保证：基于代理指标的验证**必然**失败 `[检索]`
- 推论：验证基础设施（reward signal / evaluator / monitor）必须与模型**同步演化**，不是一次性拧紧的螺丝 `[检索]`
- **SpecBench** —— 专测长周期编码 agent 的 reward hacking 的基准 `[检索]`
- 这一条**直接动摇**「可验证目标是第一原理」这个说法——不是说它错，是说它有可证明的上限

## 历史先例：Autonomic Computing / MAPE-K `[检索: 历史学家视角]`

- IBM 2001 年提出，核心是 **MAPE-K 循环**：Monitor → Analyze → Plan → Execute + Knowledge `[检索]`
- 四大「自性」：self-configuration / self-optimization / self-protection / **self-healing** `[检索]`
- 学界正统路径：把这个反馈回路当**控制论意义上的 control loop**，用控制理论设计安全可预测的控制器 `[检索]`
- **预测**（历史学家）：「loop engineering」这个**名字**可能 12–24 个月内消失，但**实践**会留下来，融入 Kubernetes reconciliation loop、SRE error budget 这类不叫这个名字的东西里 `[检索]`

## 经济结构 `[检索: 经济学家视角]`

- agentic 任务比 chatbot 多耗 **5–30 倍** token（Gartner 2026-03）`[检索]`
- 多步任务 **$0.10–$1.00**/次，是简单请求的 100–1000 倍 `[检索]`
- 推理成本每年降 60–70%，但售价不同步降 → 毛利 50%→80% `[检索]`
- **Inference FinOps** —— 治理/路由/缓存/跨厂商套利，缓存+路由可省 70–85% `[检索]`
- 关键判断：护栏最大的买家是付账企业，不是模型厂商——最佳实践主要由甲方沉淀 `[检索]`
