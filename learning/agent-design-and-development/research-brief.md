# 第 1 步 · 五视角

## 🔧 实践者

> 每天在写 agent 的工程师

**核心立场**
agent 的难点从来不在模型聪不聪明，而在上下文管理和失败恢复。从 demo 到生产的鸿沟，绝大部分是可靠性工程，不是提示词技巧。

**最强证据**
生产环境 agent 的代码里，提示词占比很小，大头是重试、超时、工具输出截断、状态持久化、幂等性。同一个模型、同一套任务，仅仅改变工具描述的写法，成功率就会出现巨大差距——这说明瓶颈在接口设计，不在模型推理。

**🔑 只有他会说的一件事**
**工具的「返回内容」比工具本身重要得多。** 大部分 agent 失败不是「模型没想到要调这个工具」，而是工具返回了 5000 行 JSON 把上下文冲垮了，或者返回了一个模型根本看不懂的错误码。实践者花在设计工具**输出格式**上的时间，远超过设计工具签名的时间。
学者不会提这个——因为论文里的工具返回值都是干净的。

---

## 🎓 学者

> 研究 agent 的人

**核心立场**
agent 能力的提升主要来自基座模型本身，而非 agent 框架或 scaffolding。同行评审的证据反复显示：许多 agentic 技巧的收益，在更强的模型上会收窄甚至消失。

**最强证据**
消融实验里反复出现同一个模式：复杂的多智能体、反思、自我批判框架，在弱模型上有明显增益，换成强模型后增益迅速衰减，有时为负。这与大众认知相反——大众认为框架是能力的来源，证据显示框架更像是在补模型的短板。

**🔑 只有他会说的一件事**
**评测本身才是这个领域最大的科学问题，而不是一个工程细节。** 学者知道多数 agent benchmark 存在训练数据污染、可复现性差、pass@k 与实际可用性严重脱节；一个 agent 在公开榜单上的分数，与它在真实仓库/真实业务里的表现，相关性远低于大众想象。
更要命的是：**很多「某某 agent 框架有效」的结论，从未被独立复现过。**

---

## 🚩 怀疑者

> 认为主流观点有问题的人

**核心立场**
「agent」这个词已经被稀释到几乎没有信息量——今天被叫做 agent 的东西，绝大多数是带循环的工作流。而真正自主的 agent，在可靠性上仍不满足严肃生产要求，因为复合错误率是数学上的硬约束，不是工程能优化掉的。

**最强证据**
单步成功率 95%，串 20 步只剩 **0.95²⁰ ≈ 36%**。这是乘法不是加法。绝大多数令人印象深刻的 agent demo，演示的都是短链路、可回滚、有人盯着的场景。真正长时程、无人干预运行的成功案例极少，且极难复现。

**🔑 只有他会说的一件事**
**支持者系统性地回避报告「无人监督下的长时程成功率」这一个指标。** 你会看到 benchmark 分数、会看到 demo 视频、会看到「节省了 X 小时」，但几乎永远看不到「在无人干预下连续运行 N 步的成功率分布」。
这个指标之所以不被报告，恰恰因为它最难看。**注意力应该放在没被报告的数字上，而不是被报告的那些。**

---

## 💰 经济学家

> 盯着钱流向的人

**核心立场**
agent 叙事在结构上由 token 消耗驱动。相比单轮对话，agent 是把推理 token 用量放大一到两个数量级的最有效方式——这意味着卖推理的一方，在结构上有推动 agent 叙事的动机。

**最强证据**
同一个任务，chat 一次消耗几千 token，agent 跑一次几十万。框架层几乎全部开源免费（争夺心智份额），而利润集中在推理侧。企业侧「替代人力」的叙事之所以能支撑高定价，是因为定价锚被设成了人力成本，而不是算力成本。

**🔑 只有他会说的一件事**
**「agent 该有多自主」这个看起来纯技术的问题，答案被商业模式扭曲了。**
更自主 = 更多步 = 更多 token = 更多收入。因此来自模型厂商的「最佳实践」，会系统性地偏向「让 agent 多试几步」，而不是「尽早失败、交还给人」。
这不是阴谋，是激励结构。**评估任何 agent 建议时先问一句：这个建议让谁多赚钱？**

---

## 📜 历史学家

> 见过类似规律的人

**核心立场**
这一幕已经演过至少四次：专家系统（80s）、软件 agent / 移动 agent（90s）、SOA/BPM 流程编排（00s）、RPA（10s）。每一轮的承诺都是「让系统自主执行多步任务」，而每一轮都在同一个地方翻车——**例外处理**。

**最强证据**
专家系统死于知识获取瓶颈与脆性：规则永远覆盖不了长尾。RPA 死于界面一改脚本就崩，维护成本最终超过了它节省的成本。**两者都不是死于「不够聪明」，而是死于环境漂移下的维护成本。** 历史上活下来的，都是被缩小范围、嵌进既有流程的版本。

**🔑 只有他会说的一件事**
**每一轮都是先热「通用自主」，最后活下来的是「窄域 + 人在环」——而且活下来的那个版本通常改了名字，不再叫原来的名字。**
专家系统活成了「业务规则引擎」，移动 agent 活成了「微服务」。据此预测：今天这批 agent 里能活下来的，五年后大概率不叫 agent 了。
还有一条判断法则：**判断一轮技术热潮到没到拐点，看的不是能力提升曲线，而是维护成本曲线什么时候穿过收益曲线。**

---

## ✅ 自查

把五条「只有他会说的」并排：

| 视角 | 独有信息 |
|---|---|
| 实践者 | 工具**输出格式** > 工具签名 |
| 学者 | 评测是**科学问题**；结论未被独立复现 |
| 怀疑者 | 被**系统性回避**的那个指标 |
| 经济学家 | 自主度的技术答案被**商业模式**扭曲 |

五条互不可替换，视角真正分开了。✅

# 第 2 步 · 矛盾图谱

> **权重调整**（据用户反馈）：学者视角「能力来自基座模型而非框架」为**已知**，降权，只作为背景。
> 历史学家视角「活下来的都改了名字 + 看维护成本曲线」为**新信息**，作为矛盾图的中心轴展开。

## 直接冲突

### ⚔️ 冲突一（核心）：历史学家 vs 实践者 —— 「例外处理」这道坎跨过去了吗

历史上四轮自动化浪潮全部死在同一个地方：环境漂移下的例外处理成本。争的是**这次是否真的不同**。

| | 实践者说 | 历史学家说 |
|---|---|---|
| **主张** | 这次不一样。LLM 能处理未预见的例外，而这恰恰是专家系统和 RPA 的死因 | 每一轮的新技术都宣称解决了上一轮的死因，然后死在同一位置的新形态上 |
| **依据** | RPA 脚本遇界面改版就崩，LLM agent 看到新界面还能试着操作；规则引擎处理不了未见输入，LLM 可以泛化 | **专家系统当年也宣称能处理长尾**——那正是它相对硬编码程序的卖点。而 LLM agent 的维护成本只是换了形态：提示词漂移、模型版本升级导致行为变化、工具接口变更、评测集腐化 |
| **要害** | 泛化能力是真实的、可观测的 | 维护成本从「改脚本」变成了「重调提示词 + 重建评测」，**但它仍在增长，而且更难度量** |

> 这是全图最关键的一条。它决定了「这次不一样」到底是真判断还是每轮都会出现的固定台词。

### ⚔️ 冲突二：历史学家 vs 怀疑者 —— 结局是「死亡」还是「改名存活」

表面结盟，实则预测完全相反。

- **怀疑者**：复合错误率是数学硬约束（0.95²⁰≈36%），过不去，所以自主 agent 到不了严肃生产。**预测失败。**
- **历史学家**：历史上这些技术**都不是死于「能力不够」**，而是死于维护成本；而且它们没有消失，是缩小范围、改了名字活下来了（专家系统→业务规则引擎，移动 agent→微服务）。**预测转化。**

**这两个预测导向完全不同的行动**：怀疑者建议观望，历史学家建议现在就去押注那个「窄域 + 会改名」的形态。

### ⚔️ 冲突三：历史学家 vs 经济学家 —— 经济力量能否推迟历史规律

两人都认为叙事被扭曲，但**拐点判据不同**。

- **经济学家**：看激励结构——谁在从这个叙事里赚钱
- **历史学家**：看维护成本曲线什么时候穿过收益曲线

**冲突点**：如果卖推理的一方持续补贴、降价、提升单位算力效率，**收益曲线会被人为托住，拐点被推迟**。那么历史规律这次会不会失效——或者只是延后？

### ⚔️ 冲突四：实践者 vs 怀疑者 —— 提高单步成功率能否击败指数衰减

- **实践者**：能。工具输出格式做对了，单步成功率显著上升，整条链路跟着变
- **怀疑者**：改变不了数学。95%→98%，20 步也只是 36%→67%，仍然不能无人值守

**真正的分歧不在数字，在结构**：能不能把任务设计成可回滚、可验证、可分段收敛，从而让链路不再是纯乘法。

### ⚔️ 冲突五（背景，已知，降权）：学者 vs 实践者 —— 框架有没有用

学者说框架增益在强模型上收窄；实践者说他每天调工具描述都在拿到实打实的提升。**其实不冲突**——实践者调的是接口契约（模型无法从内部弥补），学者测的是推理脚手架（强模型自己就会）。两者是不同的东西被同一个词「框架」盖住了。

## 证据强弱排序

| 排名 | 视角 | 为什么 |
|---|---|---|
| **1 最强** | 📜 历史学家 | **唯一有「结局」数据的视角。** 其余四个都在预测正在发生的事，只有他手上有四个已经完整收场的案例。可证伪性也最高——他给的判据（维护成本曲线）是可测量的 |
| 2 | 🚩 怀疑者 | 数学不需要证据支撑，0.95²⁰ 就是 0.95²⁰。**弱点**：把单步成功率当成了固定值，也忽略了可回滚/可验证的任务结构能改变乘法链 |
| 3 | 🔧 实践者 | 大量一手经验，且可立即验证。**弱点**：样本有偏——他只看得见自己做的那类 agent，且成功案例天然有幸存者偏差 |
| 4 | 💰 经济学家 | 激励结构分析可靠。**弱点**：有发生学谬误风险——「提出者有动机」不等于「结论是错的」。token 消耗大也可能只是因为任务真的需要 |
| **5 最弱** | 🎓 学者 | 用户已知，且**他的证据基础被他自己的批评所削弱**：他指出 agent 评测存在污染和不可复现——而他用来支撑「框架无效」的消融实验，同样来自这个评测体系 |

> 学者排最弱不是因为不重要，而是因为**他诚实地拆了自己的台**：如果评测不可信，那么基于评测的结论也不可信，包括他自己的。

## 🎯 一旦有答案就能化解最大矛盾的问题

> **同一个 agent，在环境发生自然漂移之后（依赖升级、界面改版、模型版本更新），在不做人工干预的前提下，它的成功率半衰期是多长？**

为什么是这个问题：

- **半衰期长** → 实践者对，LLM 的泛化确实跨过了那道历史的坎，「这次不一样」成立
- **半衰期短** → 历史学家对，维护成本只是换了形态仍在增长，第四轮剧本继续上演

而且它**一箭三雕**：顺带回答了怀疑者关心的长时程可靠性，和经济学家关心的真实总拥有成本。

它还是**可测量的**——这是它比「agent 会不会成功」这类问题有价值的地方。

---

## ✅ 所有视角都同意的

> 连立场最对立的实践者和怀疑者都到了同一个结论，可以当地基用。

### 1. 窄域 + 明确边界 + 人在关键节点，是目前唯一被反复验证有效的形态

五条路径完全不同，终点一致：

- 🔧 实践者：可靠性工程要求缩小状态空间
- 🎓 学者：框架增益在窄任务上最稳定
- 🚩 怀疑者：短链路、可回滚才是 demo 有效的真正原因
- 💰 经济学家：只有窄域才有可计算的 ROI
- 📜 历史学家：历史上活下来的全是窄域

### 2. 评估 agent 要看「失败时会怎样」，而不是「成功时多惊艳」

五个视角以五种方式指向同一件事：实践者看失败恢复，学者看评测有效性，怀疑者看未被报告的失败率，经济学家看失败的成本由谁承担，历史学家看例外处理。

---

## ⬛ 没有任何视角提到的（领域盲区）

### 🔴 主盲区：使用 agent 的人自己会发生什么变化

**五个视角都把「人」当成恒定的、外部的变量。** 实践者看系统，学者看模型，怀疑者看指标，经济学家看钱，历史学家看技术周期——**结构上没有一个人在看操作者的技能曲线。**

但自动化史上有一个反复出现的效应：**系统越自动，人越少练习；而恰恰在系统失败、需要人接管的那一刻，人的接管能力已经退化了。**

这直接攻击了上面那条共识：

> **「人在环」是所有视角一致同意的解药，但它的有效性会随时间自我侵蚀。**
> 一个依赖人兜底的设计，如果同时让人失去了兜底的能力，那它只是把失败推迟，不是避免。

**对带团队的人，这条是立刻能用的**：如果团队用 agent 写代码，初级工程师的成长路径会怎样？谁来做那个还能看懂 agent 产出的人？五年后这个人从哪来？

### 🟡 次盲区：出错后的责任归属

没有任何视角提到——agent 造成损失时，责任在开发者、部署方、模型提供方还是操作者。这个问题的答案会**反向决定架构**（决定了哪些环节必须留人签字），但五个视角都只在技术和经济层面讨论，没人碰组织与法律层面。

# 第 3 步 · 综合简报

## 60 秒总结

Agent 设计的真实难点不在模型推理，在两处：**工具接口与上下文管理**（工具返回什么、返回多少，比调用哪个工具更决定成败），以及**复合错误率**（单步 95% 串 20 步只剩 36%，是乘法不是加法）。目前唯一被反复验证有效的形态是**窄域 + 明确边界 + 人在关键节点**——五个立场对立的视角殊途同归到这一条。但这已经是第四轮同类浪潮（专家系统、软件 agent、SOA/BPM、RPA），**前三轮都不是死于能力不足，而是死于环境漂移下的维护成本**，并最终以缩小范围、改换名字的方式存活。所以真正该盯的不是能力提升曲线，而是**维护成本曲线什么时候穿过收益曲线**。而全场没人在看的是：依赖「人在环」兜底的设计，会随着人的技能退化而**自我侵蚀**。

## 5 个关键发现（按可靠性排序）

| # | 发现 | 支持 | 反对 / 限定 |
|---|---|---|---|
| **1** | **窄域 + 明确边界 + 人在关键节点，是当前唯一稳定有效的形态** | 🔧🎓🚩💰📜 **全体** | 无 |
| **2** | **前几轮浪潮死于维护成本而非能力不足，且以改名方式存活** | 📜（唯一有结局数据）💰（TCO 逻辑一致） | 🔧 认为 LLM 泛化改变了这一点 |
| **3** | **复合错误率是结构性约束，不是工程能优化掉的** | 🚩（数学）📜（例外处理）💰（隐性成本） | 🔧 可回滚结构能改变乘法链；🎓 强模型单步成功率在升 |
| **4** | **工具的输出格式比工具签名更决定成败** | 🔧（一手，可立即验证） | 无人直接反对，但 🎓 认为这类工程收益会被更强模型吸收；**样本有偏** |
| **5** | **「框架」一词盖住了两个不同的东西——接口契约 vs 推理脚手架** | 由 🎓 与 🔧 的冲突推导 | ⚠️ **本次综合的推论，非任何视角原话，可靠性最低** |

## 🔗 隐藏关联

> **那个最该被测量的指标（漂移后的成功率半衰期），是被三种激励结构联合封杀的——而不是碰巧没人做。**

- 💰 **模型厂商没有动机测**——测出来若显示「该更早失败交还给人」，等于建议减少步数、减少 token
- 🎓 **学界测不了**——需要长期运行真实系统观察腐化，不是 benchmark 能做的，也不产出论文
- 🔧 **实践者测了但不发布**——既是竞争优势，数字也难看

**三个方向的激励叠加，恰好都指向「不测这个」。**

单一视角都看不到全貌：经济学家看到动机但不知道是哪个指标；怀疑者知道指标缺失但归因为「支持者故意回避」；历史学家知道该看维护成本但不知道为什么没人报告。**三个放在一起，才看出这是结构性的，不是疏忽。**

## 🎯 行动建议（角色：对外输出 / 带团队）

**别再讲「agent 能做什么」，改讲「agent 在什么条件下会坏、坏了谁接」。**

**对外输出——把判据做成招牌，而不是做法**

教人怎么搭 agent 的内容已经饱和，且半年就过时。差异化在于给判断框架——维护成本曲线、漂移半衰期、「框架」一词的歧义拆解。**判据不会过时，做法会。** 尤其「维护成本曲线穿过收益曲线」这条，用户自己刚获得它，说明市场上仍稀缺。

**带团队——一件几乎没人在做的事**

引入 agent 的同时，**建立「无 agent 演练」机制**：定期让工程师在没有 agent 辅助下完成一个代表性任务。这是针对主盲区（自动化悖论）的直接对策。

以及：**明确指定谁是那个「还能看懂 agent 产出的人」，把它当作显式培养目标**，而不是假设这种人会自然存在。五年后需要他，而他需要五年养成。

## 🔮 前沿问题

> **当模型开始把 agent 循环内化（规划、工具调用、自我纠错都在模型内部完成），「agent 设计」作为一门独立学科还剩下什么？**

- 若答案是「只剩工具接口设计 + 评测设计」→ 今天绝大多数 agent 框架和教程都是**过渡性脚手架**，历史学家的「改名存活」就此兑现
- 若答案是「编排在结构上无法被模型内化」→ 这是一门可持续的学科

**答案直接决定该教什么、团队该练什么。** 押错方向的代价，是花两年培养了一批很快不再需要的技能。

# 第 4 步 · 同行评审自检

## 🔴 结构性缺陷：五个视角不是独立信源

**五个视角全部由同一个模型、在同一次生成里产出。** 所以「五个视角都同意」**不构成证据**——那不是五方独立验证，是从同一先验分布里采了五个样本。

发现 #1 的核心支撑理由（全体一致）因此大部分是幻觉。发现本身可能仍对，但对的理由不是「五个人都这么说」。

> 这是 STORM 式方法的固有代价，不是本次执行的失误。但说破它，和假装五个视角独立，是两回事。

## 可靠性打分

| # | 发现 | 分数 | 理由 |
|---|---|---|---|
| 1 | 窄域 + 边界 + 人在关键节点 | **7** | 内容本身 8（有大量外部经验支撑），但「全体一致」这个支撑理由只值 4。综合 7 |
| 2 | 前几轮死于维护成本而非能力，改名存活 | **6** | 历史结局是事实，但**「死因是维护成本」是诠释不是事实**（专家系统同时受限于当时算力与知识表示）。「改名存活」的映射经不起推敲——**微服务的思想谱系并不主要来自移动 agent，该类比是修辞性而非谱系性的** |
| 3 | 复合错误率是结构性约束 | **5** | 数学是 10 分**但模型是错的**：假设每步独立、成功率恒定，而真实 agent 有验证、重试、回滚，错误不独立，部分步骤失败无害。**0.95²⁰ 是糟糕上界，当成「结构性约束」是把玩具模型当定理** |
| 4 | 工具输出格式 > 工具签名 | **7** | 一手且可立即验证。但「更决定成败」是比较级主张，**无对照实验**，样本有偏 |
| 5 | 「框架」是词汇陷阱 | **4** | 本次推论，无外部支撑。给 4 不是因为错——**它可检验**（去看消融实验具体测什么）——而是目前只是假说 |

五条 4–7 分，无一到 8。

## 最没把握的结论

**发现 #2**（历史学家）。需要：

- 专家系统与 RPA 项目**终止原因的一手调查**，而非事后回溯叙事（回溯叙事天然偏向讲完整故事）
- 「改名存活」需**谱系证据**：微服务提出者是否真的援引过移动 agent，还是事后附会
- RPA 厂商客户流失原因数据

## 占比过大的视角

**📜 历史学家，明显超配。**

必须说破：**加权是因为用户说它新，不是因为证据更强。**

且第 2 步给它排「证据最强」的理由（唯一有结局数据）本身有漏洞：**有结局数据 ≠ 对结局的解释正确。回顾性叙事恰恰最容易过拟合**——结局已知，总能编出一条通向它的因果链。

## 该加的第 6 个视角

### 🛡️ 安全研究者（严重遗漏）

**五个视角无一提到 prompt injection、权限边界、agent 被诱导执行破坏性操作。** 对一个「让系统自主执行多步任务」的领域，这是结构性缺失。

**加入后改变结论**：「窄域 + 人在环」的理由从**可靠性**扩展到**安全**，而两者寿命不同——可靠性理由会随模型变强而减弱，**但安全理由不会：模型再强也不解决「被恶意输入操纵」，那不是能力问题，是信任边界问题。**

故发现 #1 应改写为：**「在可靠性维度上是当前有效，在安全维度上是长期必要」**。

次选：**一线操作者**（被 agent 改变工作的人），与主盲区呼应。

## 🎓 斯坦福教授评审：6 / 10

1. **停止把「全体同意」当可靠性依据**——五视角同源。要么取真实五方材料，要么把「共识」降级为「该模型的先验」
2. **无一条结论给出可证伪的预测与时间点**——「五年后不叫 agent」需说清什么算兑现、什么算证伪
3. **历史类比缺谱系证据**，目前是修辞非论证
4. **缺安全维度**
5. **定量主张用了未检验的独立性假设**，0.95²⁰ 必须标注前提

## 净效果

简报可信度下调，可用性上升。现在清楚：

- **可直接对外讲**：#1、#4
- **讲时必须带前提**：#3（说独立性假设）、#2（说这是诠释不是事实）
- **只能当假说抛出**：#5
