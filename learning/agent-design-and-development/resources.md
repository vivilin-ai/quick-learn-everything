# 资源清单：Agent 设计与开发

> 第 5 步产出。**只有 5 个。** 角色：对外输出 / 带团队 → 偏向能形成判据的资源，而非 API 手册。
> ⚠️ 标「请核实」的条目使用前先搜索确认。本领域变化极快，注意核对发布日期与当前版本。

## 1. Anthropic《Building effective agents》（工程博客）

| | |
|---|---|
| **为什么比同类强** | 做的正是发现 #5 的词汇拆解——把 **workflow 与 agent 明确分开**，主张从最简单模式开始、只在必要时加复杂度。市面上多数内容鼓吹复杂编排，它在做减法 |
| **怎么用** | 读，抄下它对各模式的分界线定义 |
| **花多久** | 1 小时 |
| **关键点** | **「大多数场景不需要 agent，需要的是 workflow」**——对外输出最好用的开场，反直觉且立刻降低听众焦虑 |

⚠️ 标题与出处有较高把握，**请搜标题确认**，勿直接引用转述的路径。

## 2. Lisanne Bainbridge《Ironies of Automation》(1983, Automatica)

| | |
|---|---|
| **为什么比同类强** | **主盲区的一手学术来源，1983 年就写清楚了。** 论证：自动化程度越高，操作员练习越少，而恰在系统失败需人接管时，人的能力已退化 |
| **怎么用** | 读。短，每段都能改写成 agent 语境 |
| **花多久** | 1–2 小时 |
| **关键点** | **「人在环」不是静态解药，它会自我侵蚀。** 四十多年前的论文精准预言今天的困境——对外输出王炸素材，把热点接到长期规律上 |

⚠️ 作者/标题/年代有较高把握；**期刊卷期请自行核对**。

## 3. OWASP Top 10 for LLM Applications

| | |
|---|---|
| **为什么比同类强** | 补第 4 步指出的结构性遗漏。少数把 agent 风险**清单化**的公开资料，其中 **Excessive Agency** 一项几乎是为本主题写的 |
| **怎么用** | 查阅式读，重点 Prompt Injection 与 Excessive Agency |
| **花多久** | 1.5 小时 |
| **关键点** | **安全理由与可靠性理由寿命不同**——模型变强削弱可靠性理由，但削弱不了「不能信任不可信输入」。这是「人在环」长期必要的真正依据 |

⚠️ **该清单有版本迭代，条目会变。** 必须去 OWASP 官网看当前版本。

## 4. Simon Willison 的博客（simonwillison.net）

| | |
|---|---|
| **为什么比同类强** | **解决时效性的那个资源。** 前三个静态，这个是活的。长期写 prompt injection 与 LLM 工具使用，符合「讲权衡不只讲结论」——会明确说什么还没解决 |
| **怎么用** | 订阅 + 按标签翻归档，不要试图读完 |
| **花多久** | 持续；首次翻归档 2 小时 |
| **关键点** | **prompt injection 至今无通用解法。** 知道这点，对外分享时就不会把安全说得太轻松 |

## 5. 所用模型厂商的官方 tool use / function calling 文档

| | |
|---|---|
| **为什么比同类强** | **唯一的动手锚点。** 对要对外输出的人，最大可信度风险是**从没亲手写过一个 agent**。任何二手教程都不如官方文档 + 自己写一遍 |
| **怎么用** | **练**：写一个 ≤100 行、不用任何框架的 agent 循环（模型 → 工具调用 → 结果回填 → 再循环） |
| **花多久** | 3 小时 |
| **关键点** | **agent 循环的本质少得可怜**——一个 while 加一次工具分发。写过才不会被「框架」唬住，也才有资格讲发现 #5 |

## ⛔ 被高估的 / 该躲开的坑

| 坑 | 为什么躲开 |
|---|---|
| **「X 行代码搭一个 agent」类教程** | 教框架 API 而非判断力，**半年过时**。对要对外输出的人尤其有害——会把保质期很短的东西讲成体系 |
| **多智能体角色扮演演示**（CEO + 工程师 + QA agent） | 演示效果极好，但消融证据显示增益在强模型上收窄。**容易学到很快过时的心智模型** |
| **榜单分数**（SWE-bench 一类） | 存在污染与不可复现。**对外引用是可信度陷阱**——懂行的人会立刻打折 |
| **全自主 agent 演示视频** | 正是「系统性回避长时程成功率」的典型形态 |

## 一周路径

| 天 | 做什么 | 完成标志 |
|---|---|---|
| **1** | 资源 1，抄下 workflow / agent 分界线 | 能用一句话说清两者区别 |
| **2** | 资源 5，手写无框架 agent 循环 | 循环跑通，调用至少 2 个工具 |
| **3** | **故意让工具返回 5000 行输出，观察后果** | 亲眼见到上下文被冲垮——**一手验证发现 #4** |
| **4** | 资源 3，重点 Excessive Agency + Prompt Injection | 能说出 Day 2 循环里存在的 3 个风险 |
| **5** | 资源 2（Bainbridge） | 能把 1983 年的论点改写成 agent 语境 |
| **6** | 资源 4，翻归档挑 prompt injection 系列 | 订阅完成，读 3–5 篇 |
| **7** | **输出**：写一篇或做一次分享，题为「**agent 在什么条件下会坏，坏了谁接**」 | 讲稿完成 |

**Day 3 是特意设计的**：用亲身实验验证发现 #4，而非转述。
**Day 7 直接服务角色**：一周输入在第 7 天压缩成一次输出。
