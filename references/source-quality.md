# 信源筛选与防幻觉

第 1 步（信源前置）用。也适用于任何时候需要评估「这个资料该不该信」。

第 1 步的硬约束是**只给 5 个**——本文件讲的是怎么挑这 5 个、以及绝不能怎么挑。

---

## 抓取被拦截时的选材策略

出站策略拦截很常见。**不要绕过它**——但也不要就此退回全靠先验。

### 域名可达性的经验规律

| 通常放行 | 通常被拦 |
|---|---|
| 代码托管：`github.com`、`raw.githubusercontent.com`、`gitlab.com` | 个人博客、独立域名 |
| 论文库：`arxiv.org` | Medium、Substack、newsletter |
| 官方文档：厂商 docs 站、语言/框架官网 | 营销站、内容农场 |
| 包与注册表：`pypi.org`、`npmjs.com` | 需登录的站点（X、部分微信公众号） |
| 标准与 RFC | |

**这只是经验，每个环境的策略不同。** 实际做法是：撞到 403 就记下这个域名类别不可达，别反复重试。

### 找等价来源，而不是放弃

绝大多数概念在放行域名上有等价材料：

- 博客讲的概念 → 找 **GitHub 上的 awesome-list 或项目 README**
- 综述文章 → 找 **arxiv.org 上的 survey**
- 「最佳实践」文 → 找**官方文档的对应章节**
- 教程 → 找**项目自带的 docs/ 或 examples/**

**先花一次搜索找等价来源，再退到摘要。** 直接躺平用摘要是偷懒。

### 用户是你最好的检索代理

🚨 **用户的浏览器不在 agent 的代理后面。** 你打不开的页面他能打开。

主动开口，别等他想到：

> 这几篇我读不到（环境拦截），但你应该能打开。方便的话贴正文给我，我按原文讲。

这一条的效果远好于任何变通——**一手原文永远胜过搜索摘要**。

### 链接读不到，照样要给

**你读不到 ≠ 用户点不开。** 资源清单仍然给真链接，只是诚实标注：

> ⚠️ 这篇我没读到全文（抓取被拦），推荐理由基于搜索摘要，请你自己点开判断。

## 最高优先级：不要编造

推荐一本不存在的书，比不给推荐糟糕得多。用户会去找，找不到，然后开始怀疑你说过的每一句话——包括那些正确的部分。

**必须遵守：**

1. **不确定就标注。** 格式：`[书名]（⚠️ 请核实——我不完全确定书名/作者准确）`
2. **区分三档来源。** 读到全文标 `[检索:出处]`；**只看到搜索摘要标 `[摘要:出处]`，不要标成 `[检索]`**；靠记忆标 `[未验证]`。把摘要说成全文，是在借一个你没有的可信度
3. **URL 分两种情况**：
   - **检索到的真实链接 —— 必须给。** 第 1 步的硬要求就是拿到能点开的东西
   - **凭记忆拼的 URL —— 绝不给。** 哪怕它看起来很对。宁可说「搜官方文档的 X 章节」
   这两件事常被混为一谈：禁止的是**编造**链接，不是**提供**链接
4. **不虚构版本号、章节号、页码。** 说「大概在讲配置的那几章」，不要说「第 7 章第 3 节」
5. **模糊记忆就说模糊。** 「有一本讲 X 的经典教材，作者我记不准了，你搜 ___ 关键词应该能找到」——这是诚实且有用的
6. **明确交代知识时效。** 「我的信息可能截止到某个时间点，这个领域变化快，请核对发布日期和当前版本」

一次编造带来的信任损失，抵得过十条准确推荐。

## 五类信源

每类推 2–3 个，各有各的用途，不要都推同一类。

| 类型 | 作用 | 挑选要点 |
|---|---|---|
| **入门读物** | 建立框架 | 讲「为什么」多过「怎么做」；能容忍它不精确 |
| **权威参考** | 查证与深挖 | 官方文档、领域公认的标准教材。不要求好读，要求准 |
| **实践教程** | 动手 | 有完整可跑的例子；注意时效，教程最容易过时 |
| **社区与动态** | 跟上变化 | 论坛、邮件列表、会议。用来知道现在大家在吵什么 |
| **值得跟的人** | 判断力 | 长期在这个领域产出、且会讲权衡而不只讲结论的人 |

## 每条信源必须标注

- **为什么推荐它** —— 它比同类好在哪，别只说「经典」
- **适合哪个阶段** —— 入门期看还是有基础后再看。把进阶资料当入门推荐是新手劝退的头号原因
- **大概要花多久** —— 用户要拿它排进时间预算
- **时效性** —— 内容会不会过时，多快过时

---

## 说出你不推荐什么

领域里总有流传极广但对入门有害的资料。点出来并说明原因，这部分信息的价值常常高于推荐本身。

三种典型：

- **已过时但仍在流传** —— 讲的是好几个版本前的做法，照着做会撞一堆现在不存在的问题
- **把复杂问题讲油滑** —— 读着爽，但抹掉了所有权衡和边界，读完自以为懂了。这类最危险
- **伪装成入门的进阶资料** —— 默认读者已经有大量背景知识。用户读不懂会归咎于自己不够聪明，然后放弃

## 质量信号

**加分：**
- 讲权衡和适用边界，而不只给结论
- 明确说「这个方案在什么情况下不适用」
- 有更新记录，作者会修正旧内容
- 引用一手来源，而不是转述转述的转述

**减分：**
- 通篇「最佳实践」，不谈代价
- 没有日期，或日期很旧却在讲快速变化的话题
- 关键论断没有出处
- 大量篇幅在贬低替代方案，而不是说清自己的适用场景

---

## 快变领域的额外提醒

技术栈、AI、法规、市场类的领域，**知识有保鲜期**。这类领域的信源清单要：

- 明确标注每条的「大致新鲜度」
- 提高「社区与动态」类的权重——静态资料在这里很快失效
- 提醒用户：**遇到与实际行为不符的，以官方文档和实测为准，不要以我说的为准**
